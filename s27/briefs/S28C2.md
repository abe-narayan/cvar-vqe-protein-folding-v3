# S28 LANE C2 -- THE RECOGNITION AUDIT: WHICH NATIVE-FREE SCORER, IF ANY, PREFERS THE 0.3 A STRUCTURES THE CIRCUIT FAMILY CAN EXPRESS?

Second-wave brief for the lane that finishes lane C's Part 2. Read `s27/S28_CONTRACT.md`
(with addendum 1) first, then S28-L1b, S28-L13, S28-L17 and lane A's recognition entries.

## The new angle, stated up front
S28-L1b (lane A, ORACLE): the deployed circuit read as signed affine weights reaches 0.29 to
0.42 A on every target (ORACLE, theta chosen against the native), against 3.05 A for the
convex average. Lane A's recognition arms ask whether ONE objective (the shipped distogram
Bayes-risk of the emitted structure) finds them. S27 measured 18 native-free channels on POOL
MEMBERS and found none that helps the average. Nobody has measured any native-free scorer on
OFF-POOL structures: the signed combinations the family can express. That is the question.
If no scorer prefers the ORACLE structure to the production output, recognition is closed for
the whole S27 channel library in one measurement, and the report can say exactly what an
objective would have to know. If one does, it is the candidate objective for a lane A2 run.

## Design (ORACLE DIAGNOSTIC throughout; nothing here is deployable)
- Inputs, per target: the production structure (DIS top-75 uniform average, point cloud, and
  its built chain) and the ORACLE circuit structure from `s27/results/s28_A_oracle_rows.jsonl`
  / `s27/results/s28_A_structs/<pdb>.npz` (the best-of-5 start and the single-start seed 0, both;
  the best-of-5 is an order statistic, S28-L13). Add the ORACLE random-27-subspace structure
  (0.61 A) as a third point so the audit has a ladder, not a pair.
- Scorers: every native-free channel a CA trace supports directly (DIS Bayes-risk, DISTPOT,
  CONTACT, ENV, RG_LAW, RG_UNIV, EXVOL, CAGEO, CONS-typicality against the pool, DMAP_CONS,
  SS_MATCH via the CA-only caller if one exists) and, through the built chain, the backbone
  channels (RAMA, LEG terms, AMB if one AMBER process fits the box). Use `s27/ham_lib.py`
  functions on a one-candidate Context where they accept it; write a thin adapter where they
  do not, with a test that the adapter reproduces the pool-row value on a pool member.
- Statistic, per scorer: the fraction of targets on which the scorer prefers the ORACLE
  structure to the production structure (pairwise sign accuracy), with its binomial CI, the
  fold-clustered CI, and the same against the 0.61 A subspace structure. A scorer that prefers
  the ORACLE structure on more than 50% of targets with the fold CI excluding 0.5 is a candidate
  recognition signal; below 50% it is anti-recognition on this family (as CONS was on the pool).
- Controls: (i) the scorer's preference between the production structure and a RANDOM signed
  combination of the same family at the same RMSD scale as the ORACLE structure, so "prefers
  the ORACLE structure" is not "prefers any signed combination"; (ii) the scorer's preference
  between production and a Gaussian-perturbed production structure at 0.3 A (same distance,
  no information). (iii) the FAIL18 / 108 split.
- Falsifier (this is a diagnostic, so the falsifier is for the closure claim): "recognition is
  closed on this family" is FALSIFIED if any scorer, or any nested-CV linear combination of
  scorers, prefers the ORACLE structure with sign accuracy whose fold CI excludes 0.5 AND beats
  control (i). Registered prior: the distogram Bayes-risk prefers the ORACLE structure on a
  minority of targets (the native is at its 37th percentile, S8-9); the geometric channels
  (EXVOL, CAGEO, RG) prefer production because the ORACLE structure is an off-manifold signed
  combination; nothing clears 0.5 against control (i).
- Cost: classical, seconds per target for the CA channels; the built-chain channels are 3 s
  per target per structure; budget and checkpoint. One AMBER process if AMB is included.
